🏗 System Architecture — End-to-End Flow

🔍 InputResolver

Expands catalog/schema/table inputs into flat TableSelection list. Paginates SHOW TABLES via SQL API.

📦 BatchPlanner

Greedy First-Fit-Decreasing bin-packing. Sorts tables by size DESC, fills chunks to chunk_capacity_gb.

⚡ BatchChunkScheduler

ThreadPoolExecutor(max_workers=max_concurrent_chunks). One Future per chunk — sliding window concurrency.

🖥 ChunkWorkerNotebook

Runs on 8-executor cluster. ThreadPoolExecutor(parallel_threads) copies tables simultaneously via spark.sql().

🗄 Deep Clone Modes

🔗
Delta Share Mode
clone_type = delta_share
Source table is accessible via Unity Catalog FQN (same metastore or Delta Sharing). Clone uses fully-qualified name directly.
-- Clone SQL generated:
CREATE OR REPLACE TABLE
`tgt_cat`.`schema`.`table`
DEEP CLONE
`src_cat`.`schema`.`table`
✓No path resolution needed
✓Works across UC metastores via Delta Sharing
✓No ADLS firewall/storage credential issues
⚠Requires source catalog visible on target
💾
Direct ADLS Mode
clone_type = direct_adls
DESCRIBE DETAIL resolves the abfss:// path of the source table. Clone uses the raw ADLS path — no UC dependency on source.
-- Clone SQL generated:
CREATE OR REPLACE TABLE
`tgt_cat`.`schema`.`table`
DEEP CLONE delta.
`abfss://container@acct.dfs.../path`
✓Works across completely separate metastores
✓No Delta Sharing setup required
⚠Requires External Location on target for src ADLS
⚠Managed UC tables → falls back to FQN clone
🔀 Automatic Fallback Logic (in chunk_worker_notebook)
if clone_type == "delta_share":
clone_sql = FQN clone # CREATE OR REPLACE ... DEEP CLONE `src`
elif src_path.startswith("abfss://"):
clone_sql = ADLS path clone # DEEP CLONE delta.`abfss://...`
else: # no ADLS path (managed UC table, same metastore)
clone_sql = FQN fallback # avoids LOCATION_OVERLAP errors
